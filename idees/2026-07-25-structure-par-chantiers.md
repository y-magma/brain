# Idée : structure par chantiers (pas par étapes)

- **Date** : 2026-07-25
- **Proposé par** : IA (critique de structure)
- **Statut** : graine
- **Échelle(s)** : communauté (atelier) · individu (contributeur)
- **Thème(s)** : méthode · structure du dépôt · anti-blabla
- **Slogan / expression associée** : « Fermer des boucles, pas ouvrir des dossiers. »
- **Prochaine étape** : débattre · décider
- **Priorité** : haute

## La graine

Aujourd'hui le dépôt coupe le travail par *étape* (`idees/` → `points-de-vue/` → …). Pour un sujet (ex. atlas), on multiplie les fichiers épars et on peine à fermer la boucle.

Proposition : couper par **chantier** (un sujet vivant). Un dossier = un fil. Dedans, 4 pages qui évoluent :

| Fichier | Rôle |
|---------|------|
| `seed.md` | Graine + slogan |
| `debate.md` | Steelman pour / contre |
| `map.md` | Convergences / divergences / angles morts |
| `formula.md` | Formule(s) + raisonnement |

`decisions/` et `vision/` restent transverses. Archiver = déplacer le dossier chantier entier.

## Pourquoi ça compte

- Aligne « peu de verbalisation » : un sujet = un lieu, pas 5 copies de liens.
- Rend visible le **trou** (pas de `map.md` = boucle ouverte).
- Garde steelman + Git + humain décide.
- Se rapproche d'IBIS / wiki vivant sans abandonner les slogans.

## Ce qu'on ne sait pas encore

- Migrer l'existant ou dual-run (nouveaux chantiers seulement) ?
- Où vivent les *accroches* hors chantier (noyau global) ?
- Docsify / sidebar : auto-liste des chantiers ?

## Nature des énoncés

- **Faits** : `syntheses/` était vide ; archive > idées actives ; sujets éclatés multi-fichiers.
- **Valeurs** : préférer boucles fermées à exhaustivité de dossiers.
- **Hypothèses** : un dossier-chantier réduira la friction sans tuer l'anti-populisme.
